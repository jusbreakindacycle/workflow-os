# Product Brief

## Working description

Workflow OS is the temporary name for a personal, local-first command center and autonomy layer that lets one solo builder operate an AI-native delivery business across multiple clients/projects without becoming the manual dispatcher between AI tools.

## Primary user

One technical or AI-assisted solo builder delivering websites, applications, automations, internal systems, data/integration work, AI features, process improvements, and maintenance.

## Core problem

Even when individual AI tools are capable, the human often remains the coordination bus: client request in chat/notes, research in one AI, architecture in another, implementation in a coding agent, tasks in Markdown/memory, approvals in chat, code/source control elsewhere, deployments/automation/monitoring elsewhere.

The human still transfers context, chooses what to prompt next, remembers dependencies, and verifies what actually happened.

## Product answer

Create one canonical operating layer that:

- accepts raw project/client input;
- asks adaptive questions and preserves unknowns;
- distinguishes requested solution from underlying problem;
- chooses a case-specific delivery strategy instead of assuming custom software;
- records commercial commitments separately from internal approvals;
- creates explicit Project/WorkItem/revision state;
- generates a strict case-specific Project Pack and minimum Context Slices;
- chooses eligible models/runtimes/connections/skills dynamically;
- activates only needed internal specialist roles;
- runs bounded loops/routines;
- captures evidence and Activity events;
- asks the operator only for consequential authority/new spend;
- continues through deployment and maintenance.

## UX thesis

The main UI is an **owner/operator cockpit**, not an agent chatroom.

Primary surfaces: New Project / Revise Goal, Needs My Attention, Activity Feed, Projects, Clients/Engagements, Costs, Production/Maintenance, Settings/Providers. Detailed worker/provider logs are drill-down diagnostics.

## Non-goals

Workflow OS is not its own foundation model, universal IDE, source-control replacement, universal workflow engine, generic remote desktop, prompt marketplace, full accounting ERP, unrestricted self-organizing swarm, or a system that silently spends money/changes client scope.

## Differentiation

The differentiator is not “more agents.” It is case-specific Project truth; solution-strategy challenge; commercial + delivery context; provider-neutral model/runtime/connection routing; generated instruction projections; bounded loops; human authority; cross-provider evidence; production/maintenance ownership; and one operator attention surface.

## Product principle

> Automate coordination, not accountability.
