# /scope-mvp

Canonical source: `docs/product/scope-mvp.md`.

When invoked:

1. classify the proposed task as **MVP-required**, **MVP-supporting**, **future/deferred**, or **out-of-scope**;
2. cite the relevant scope/acceptance requirement by repository path/heading;
3. refuse to silently expand implementation scope;
4. if expansion is genuinely necessary, propose the smallest ADR/scope change for human approval.

The scale-trigger matrix is not an MVP feature list.
